# 发布回读

旧状态机：审核通过 → 负责人确认/预告（经营程序推进）→ 渠道额度预留 → publishing（发布程序）→ publish-lookup（15分钟、1小时定时器）→ QA/verify（再次15分钟、1小时定时器）→ observing/closed（经营程序）。异常进入blocked，由CEO或币安专用恢复程序处理。跨日未知预留不释放，导致一篇卡住整个渠道；发布回执与后续验收分离又增加了一层等待。

新状态机：预检 → 提交 → 同次运行回读 → 已发（链接）／确认未发／未知。两渠道共用提交、回读与安全重试框架；小红书适配器核对作者最新笔记的标题、正文、图片及时间，最多约两分钟轮询，币安适配器核对官方编号或分享链接。缺少查帖证据不能把超时或笔记暂不可见判作未发。

已发直接结案或进入效果观察；明确未发最多同轮再试一次，后续经营周期通过原任务、原确认及额度门槛重试。未知只锁原稿，后续每个五分钟经营周期最多一次只读回查，共三次，耗尽后需人工并列入日报。当天额度按已发＋未知＋尚未执行的当日预留计数，明确未发释放额度；跨日未知不锁整个渠道。

既有-result.json继续作为结果凭据；旧任务及定时器仍可只读接续，不创建新验收定时器。一次性运行 `node cli/company-publication-import.ts /private/company/company.json` 为在途旧任务补入原编号回读记录；先在私有线上副本验证，再停必要服务、备份并部署。导入不执行发布、不回答卡片、不派模型；内核与HTTP协议不变。
