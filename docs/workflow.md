# 公司流程

时间均为北京时间。本文描述启用 `delegation.source` 后的现行流程；旧配置审批兼容见公司协议。记住保持暂停，今朝和 rabbitrun 按在岗目标推进。

## 每周

| 时间 | 谁负责、产出什么 | 卡住时怎么办 |
|---|---|---|
| 周一工作日 09:00 后 | CEO 先读上周周报、员工复盘和工作笔记，为在岗员工续上本周目标与当天安排 | 缺目标由 15 分钟巡检交 CEO 补齐；已有确认目标的新业务由程序补齐缺失的安排摘要。改变方向由CEO决定，花钱另请董事长 |
| 周一上班后，错过则下个正常工作日补开 | 记住、今朝、rabbitrun 运营报题：本周目标扣除已发、备稿和制作中稿件，再加一条备选，每批最多十条；剩余目标为零不重复报题 | 选题会只报标题、角度、依据、结构、关联业务、平台，不写正文；运行故障按原任务有限重试 |
| 报题后 | CEO按对应手册五项打分，≥7直接入池，<7退回员工换题，记录理由 | 不发董事长选题卡，未通过不写稿 |
| 工作日池中选题不足时 | 运营按剩余目标补报，仍走CEO评分决定 | 未拍板不写稿；旧在途稿继续原流程，不补选题审批 |
| 周五 | 不再向董事长索要数据 | 缺失数据标未知，照常复盘 |
| 周五 18:00 后 | 每位在岗员工各做一轮复盘：目标与实际、逐帖数据、选题效果、原因、下周打算，并整理本人笔记 | 计入员工额度；临时运行或格式失败沿原任务有限重试。未交齐不无限等人 |
| 员工交齐，或周五 19:30 到时 | CEO 汇总日报和周报、整理管理笔记 | 原任务失败可有限重试；缺数据、未交复盘如实列出 |
| 周五 21:00 | 程序发送一条“日报+周报”；晚完成则完成后补发 | 21:15 后巡检检查是否生成、送达；普通阻塞记维护清单，仅支出和必须本人验证请董事长 |

## 每天

| 时间 | 谁负责、产出什么 | 卡住时怎么办 |
|---|---|---|
| 工作日 09:00 后 | CEO 给当天安排；员工完成一次上班规划，沿用已有事项，再由程序分别派工 | 凌晨预先写的安排仍需 CEO 在 09:00 后确认；周末不新增上班规划和选题会。已批准的发布排期仍按每天执行 |
| 每五分钟经营周期 | 固定程序推进任务、审核、卡片答复和到期事项；不靠模型空转维持流程 | 队列和已发事件持久保存；正常重启接续，重复结果、答复按编号去重 |
| 工作日 09:00–22:00，每十五分钟 | 程序巡检未开工、无效等待、审核积压、失败/超时/认证、连续空转、额度、确认卡、X 待发和日报 | CEO 可撤销无效等待、有限重试安全内部任务、补审、调整安排、暂停/恢复自己暂停的员工。真实等待不会被擅自解除，等待拍板不误报为员工没开工 |
| 发现异常后 | CEO核对并处理，不能自行处理则记后台“待维护者处理” | 只有新增支出和必须本人验证才请董事长；X超时只写日报一句，不催促 |
| 每五分钟独立看门狗 | 检查引擎、后台、回调服务和经营心跳 | 服务不可用或心跳超过十五分钟，直接提醒董事长检查服务器；不依赖 CEO，按故障去重。飞书也不可用时保存待发送记录 |
| 09:35 后 | 只读入口每天尝试采集一次小红书数据，形成效果资料；笔记追加已核实数据与意见 | 读取失败写未知；登录/平台阻塞暂停采集并交维护者；必须本人验证才通知董事长。rabbitrun 当前仅记录发布回执，效果数据可由董事长自愿补录，缺失标未知，不自动抓取 |
| 全天 | 每业务制作中与待发备稿合计最多两篇；选题池不算成稿。到额度的模型任务保留，次日再排 | 已确认未进行模型工作的启动/认证失败退还额度，未知失败不退；等待不占模型进程；固定发布、核验、巡检不占模型额度 |
| 20:30（启用巡检）或 21:00（未启用） | CEO 沿当天唯一汇报任务生成日报，程序完成后发出；员工日报从当天回执汇总，无工作照实写 | 已登记的当日日报豁免 CEO/总额度拦截，实际用量仍记账；周五改走上表。普通日 20:45 起检查送达；首次失败记维护清单，并沿原任务有限重试；跨日未完成保留记录，不占住新一天的管理和日报 |
| 跨天、跨周 | 发布和模型额度按北京时间零点切换；周目标按周一切换；未完成稿件、审批和 X 待发保留 | 新周先续目标；旧稿不丢、不重复发布，旧题不被新一轮选题会重新扣住 |

## 每篇稿子

| 步骤 | 谁负责、产出什么 | 卡住时怎么办 |
|---|---|---|
| 取题 | 运营从已通过且未占用的池中取题，提出制作计划；程序绑定唯一选题 | 同题不能重复派工；备稿已满先完成已有稿。没有批准题只能查资料、报题 |
| 写稿 | 运营先读本人工作笔记、对应手册、内容指南和选题决定意见，交完整本地稿件与选题编号；币圈读独立指南 | 未通过选题不得写；临时运行/格式失败有限重试，事实、图片或账号问题交 CEO 判断 |
| 审稿 | CEO 读取当前交付文件和版本，决定退回、接受归档或进入发布；退回理由写入笔记 | 退回生成新一版写作任务；失败重试重新读取最新资料，旧版本结论作废。待审超过三十分钟且无排队/运行审核，由巡检发现、CEO 补审 |
| 发布决定 | CEO审稿通过即决定发布并记理由，交固定程序 | 不发董事长确认卡，修改稿须重新审核 |
| 发布 | 固定程序只发 CEO 已冻结的版本。记住与今朝共用小红书每日一篇；rabbitrun 币安每日一篇 | 超额顺延，未核实的发布保留名额。缺账号、回执不明或平台失败交 CEO/维护者处理，不把本地稿当已发，不盲目重发 |
| rabbitrun 的 X | 币安 API 确认后，飞书送“X 待发”稿件 | **董事长自行在 X 发布，再点“我已在 X 发布”**；按钮只登记，不代发。未点保持待发，不阻塞币安回执，也不冒充 X 已发 |
| 回执核验 | 小红书只读回查作者、标题、正文、图片数、发布时间；币安核对已登记的官方回执，X 单列状态 | 小红书暂不可查时十五分钟、六十分钟后再查；仍失败则受阻，禁止据此重新发帖 |
| 数据与笔记 | 程序追加数据、退稿理由、董事长意见；周五员工和 CEO 各自整理笔记 | 来源与原始事实保留、重复不追加；未知数据不填零，新追加事实不会被旧复盘覆盖 |

## 董事长需要做的事

只为新增支出作决定；必须本人验证的登录或服务宕机时处理兜底通知。币安发出后收到唯一日常卡片“X待发”，本人手动发布再点确认，不催促。每天照常看日报，其中增加“今天替董事长做的决定”和“待维护者处理”摘要。其他事项交CEO及外部维护者，不再周五索取数据。

任何等待都结束本轮，不占模型进程，不代替本人验证或手动发X。
