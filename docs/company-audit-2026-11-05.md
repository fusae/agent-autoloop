# 公司运行检查

检查范围：CEO 管理、项目职责、任务派发、部门交接、异常恢复、验收、效果跟进和负责人沟通。结论：系统具备内部团队协作流程，尚未覆盖完整的对外业务运营。持续运营指推进有价值的工作，不是让所有模型始终运行。

| 环节 | 发现与本次处理 | 当前边界 |
|---|---|---|
| 派工 | 检查消耗每日额度，已批准工作被拦截；取消项目及 CEO 每日次数上限 | 保留项目在途上限、同组串行、单任务最大派工次数和暂停开关 |
| CEO 管理 | 相同问题反复检查却无决定；限制相同输入额外复查两次并通知停滞，新事实恢复 | 有新输入的合法管理不受每日次数限制；仍需模型给出有效决策 |
| 项目责任 | 页面把 CEO 显示为所有项目负责人；恢复产品负责项目、CEO 管理全局 | 当前为岗位角色，不是独立雇员账号或多租户权限 |
| 工作交接 | 原岗位可能仍显示正在执行已交给下一岗位的任务；按实际阶段显示责任与下一步 | 引擎排队与业务处理中仍是不同层次，不把派发当成交付 |
| 员工主动性 | 旧开放问题挡住新业务信号；新输入和到期复盘允许重新核查 | 没有新资料、没有待办时休眠；不会为了保持忙碌制造工作 |
| 业务知识 | 每轮读取最新账本、来源、历史问答；员工使用项目知识 | 来源有采集时间，模型不能自行扩大数据读取或执行权限 |
| 验收 | 内部工作经独立 QA，普通交付按原审批流程 | 文档验收不能证明真实用户使用、产品全部实测通过或推广有效 |
| 经营效果 | 计划包含指标与后续复盘，未知结果继续观察 | 需要真实采集口径；空白台账、内容草稿不能算增长 |
| 负责人沟通 | 默认简短汇报新增结果、阻塞及下一步；无需重复回答已有事实 | 普通聊天已接入内部目标、派工和计划审核，落账后确认；外部发布和付款尚未接入 |
| 对外执行 | 已有内部内容、代码、分析和回复草稿流程 | 发布推广、联系用户、投放付款及线上变更尚未接入公司派工；不能声称正在自动获客 |
| 费用 | 展示已上报用量，保留去重、有限修复和并发约束 | 没有新增总费用硬上限；缺报费用不能视为零 |

验证使用临时账本、真实中台和模拟员工/飞书，检查旧额度耗尽后继续派工、并发和暂停保持有效、跨项目隔离、CEO 超过24次仍处理新输入、相同待办停止空转、新事实恢复，以及岗位交接。部署后另核实已有计划进入实际执行；不改写业务历史或伪造完成状态。

CEO 对话修复：查询与内部工作共用一个 CEO Agent；普通飞书消息无需特殊指令。明确目标生成既有 executive 决策，固定协调器校验后使用相同员工、验收和效果跟进链路；重复消息不重复派工，澄清回复继续原事项，失败返回实际原因。模型仍不直接写账本或凭据。

连接误报修复：CEO 第 464 轮多次输出 turn.completed 与完整管理回执，旧 Codex 适配器却仍返回先前 Reconnecting 错误，导致已完成工作重复执行。修复后以最终完成事件及有效正文判定成功；真正失败保留重试。增加适配器回归及真实 worker/模拟进程测试，确认恢复连接后只执行一次并提交业务回执。

同次恢复发现 CEO 输出6项 evidence 超过既有1–5项校验；补齐 CEO 专用回执的数量、单项长度及总长度约束，新建与旧规则升级均覆盖。保持校验不放宽，原任务由既有有界回执修复继续。
