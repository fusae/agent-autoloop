# 流程审计记录

范围：记住、今朝、rabbitrun 的选题、写稿、审核、发布、回执、数据、笔记、周复盘及共同调度。仅修公司插件，不修改内核、篇数、额度或确认规则。

线上通过只读数据库快照核对：三项业务均有本周目标、CEO 摘要和每日安排；新选题正在初筛，既有稿件仍等发布确认。早前“新业务缺摘要”“失败重试审旧稿”的修复仍在，保留原回归测试。私有稿件、账号、消息、运行记录、数据库和备份不进入仓库。

| 问题与影响 | 根因 | 最小修复与回归 |
|---|---|---|
| CEO 漏筛后，选题可能永久停在初筛 | 事件指纹已消费；补审只考虑成稿 | 未初筛题同样进入补审条件，仍排除正在排队/运行的 CEO，且两次修复耗尽后不靠新任务绕过上限；`company-topics` |
| 没有在岗运营的业务、跨周旧题可能拖住整批选题卡 | 会前屏障覆盖所有业务、所有周次 | 只等实际参会员工，本周屏障只约束本周题；`company-topics` |
| 新选题流程可超出两篇备稿，同题可被 CEO 同轮派两次 | 开启 topics 后跳过全部备稿校验；CEO 指令未即时占题 | 保留数量校验，免除未批准时的写稿要求；同题校验并占用；`company-topics`、整周模拟 |
| 凌晨已有安排却无法上班，周末还会启动上班规划 | “缺今日安排”只看日期；工作日计算未跳周末 | 09:00 前安排列入待确认，相同安排可重新确认；跳过周末；`company-workday` |
| 日报和员工周复盘失败后只有失败记录，没有恢复者 | 恢复仅认最后管理任务和员工普通活动 | 登记的当日日报、本周复盘接入原有两次恢复；`company-reporting`、`company-weekly` |
| 旧日报跨日排队会挡住新一天管理 | 日报豁免只限原日期，但队列仍被当成有效 CEO 审核 | 原任务转为跨日未完成，不调用模型，不阻塞当前管理；`company-reporting` |
| 等拍板被报成没开工，周复盘失败漏检或成果被算空转 | 未区分真实等待，巡检只查普通活动和交付字段 | 核对等待与备稿覆盖，关联已登记周复盘，识别复盘产出；`company-health` |
| 选题卡与发布卡同轮集中产生，会超过回执上限而丢失确认入口 | 两处分别发卡，发布侧未计入选题卡占用 | 到上限保留发布待办，下周期再生成确认/预告卡；`company-publish-guards` |

验证使用假模型、假 HTTP、假飞书和合成数据；整周测试覆盖三业务、拍板前不写稿、退稿、CEO 失败恢复、每日发布限额、X 保持待发、重启、周五复盘和下周目标。实际 X 按钮、选题按钮/文字、发布确认与预告撤回分别由通道和发布守卫测试覆盖；不冒称真实外部平台完成验收。

保留的现有边界：rabbitrun 不自动抓取平台效果；X 始终由董事长发布并登记；数据未知不补零；需要认证或发布结果不确定时不得自动重发。日报豁免额度拦截但实际用量照常记账；这次不改变计数约定。
